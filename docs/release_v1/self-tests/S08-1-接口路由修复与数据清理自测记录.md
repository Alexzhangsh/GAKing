## 二、问题二：`scheduled_task_run_log` 表中 growth 系统历史数据残留

### 2.1 问题描述

E01 回滚后，`scheduled_task_run_log` 表中仍保留 2 个 growth 任务的 5 条历史运行日志：

| 任务名称 | 记录数 | 最后运行时间 |
|----------|--------|-------------|
| `growth_expire_reset` | 2 | 2026-08-15 03:00:00 |
| `daily_growth_grant` | 3 | 2026-08-15 02:19:04 |

这些任务的代码已在 E01 回滚时删除，不会再运行，但历史数据仍然占用空间并在运维监控页面可见。

### 2.2 清理方案

提供 SQL 脚本按 `task_name` 条件删除，仅清理 growth 前缀的任务数据，不影响其他定时任务日志。

### 2.3 清理脚本

**文件**：`docs/scripts/cleanup_growth_scheduled_task_logs.sql`

```sql
-- 清理前确认
SELECT task_name, COUNT(*) AS cnt
FROM scheduled_task_run_log
WHERE task_name IN ('growth_expire_reset', 'daily_growth_grant')
GROUP BY task_name;

-- 执行清理
DELETE FROM scheduled_task_run_log
WHERE task_name IN ('growth_expire_reset', 'daily_growth_grant');

-- 清理后确认
SELECT task_name, COUNT(*) AS cnt
FROM scheduled_task_run_log
WHERE task_name IN ('growth_expire_reset', 'daily_growth_grant')
GROUP BY task_name;

-- 确认其他任务日志不受影响
SELECT task_name, COUNT(*) AS cnt
FROM scheduled_task_run_log
WHERE task_name NOT IN ('growth_expire_reset', 'daily_growth_grant')
GROUP BY task_name
ORDER BY task_name;
```

### 2.4 安全说明

| 检查项 | 状态 |
|--------|------|
| 不影响其他任务日志 | ✅ 仅删除 2 个特定 task_name |
| 不删除其他表数据 | ✅ 仅操作 `scheduled_task_run_log` 表 |
| 不影响业务数据 | ✅ 日志表为纯审计用途，删除不影响业务 |
| 提供了清理前/后确认步骤 | ✅ SQL 脚本含 4 个步骤 |
