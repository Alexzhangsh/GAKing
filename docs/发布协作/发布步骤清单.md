## 一、批次状态机

```
待登记 → 待核对(Gate D) → 待测试(Gate T) → 待发布(Gate P) → 已发布(留观完成)
            ↑                  ↑                 ↑
            └── 打回重做 ──────┴─────── 打回 ────┘
```

| 状态 | 含义 | 谁推进 | 标志动作 |
|---|---|---|---|
| 待登记 | 开发中，尚未登记交接单 | Dev | 本地构建成功即登记（硬约束①） |
| 待核对 | 交接单已登记，等硬闸门核对 | Release | `bash scripts/release_check.sh <交接单>` exit 0 |
| 待测试 | Gate D 过门，测试中 | QA + PM | 回归/冒烟全绿，Gate T 过门 |
| 待发布 | Gate T 过门，等发布窗口 | Release + PM | 窗口确认 + 回滚点已建，Gate P 过门 |
| 已发布 | 生产发布完成 + 留观通过 | Monitor | 台账记录 + 移入归档 |

**状态字段格式（每行写死）**：`状态 | 时间 | 操作者`
每步流转后更新：`待核对 | 2026-09-05 22:10 | Release`

## 四、使用规则（硬约束）

1. **构建即登记**（Dev）：任何代码改动本地构建成功，必须当场在本表登记批次 + 填写交接单（小改、不马上发布也要登记）。禁止"构建了但不说"。
2. **发布前先探测未登记改动**（Release）：每次发布前必须执行 `git status --short` + 检查工作区构建产物新时间戳；发现改动但清单未登记 → 补占位批次等交接单，**禁止逆向比对产物猜开发意图**。
3. **单写者**：Dev 写「变更内容/交接单」段，Release 写「状态/核对/发布」段；同一段同一时刻只有一个写者，防互相覆盖。
4. **过门才流转**：未过 Gate D/T/P 禁止进入下一状态（判定标准见 `发布操作文档.md` §三）。
5. **任务编号严禁自创**：批次号沿用任务清单既有编号（S/B/F/M 系列），发布单号按 `REL-YYYYMMDD-NNN` 递增。
