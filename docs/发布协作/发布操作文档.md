# 金角大王 发布操作文档（可执行手册）

> 机制来源：小脉养车双 Agent 协作模式迁移（M07-5）。本文档是**执行手册**：按顺序照做，不要跳步。
> 角色映射：Producer = Dev（Trae 多实例）、Executor = Release（运维脚本 + Alex 审核）、QA、Monitor、PM 判定门禁。
> 权威环境信息见 `部署与发布手册.md`；生产铁律见 `生产发布清单.md`；批次状态见 `发布步骤清单.md`。

---

## 一、协作契约（4 条，缺一不可）

1. **文件为媒**：共享文件（本目录 + `发布步骤清单.md`）是唯一信息桥梁，禁止靠会话记忆或口头对齐；交接状态、核对结论全部落盘。
2. **单写者**：同一段落同一时刻只有一个写者；Dev 写交接单、Release 写核对/发布段，各写各的段。
3. **闭环标**：批次走到「已发布」才算交付完成；中间状态逐段留痕（`状态 | 时间 | 操作者`）。
4. **硬闸门**：`release_check.sh` 时间戳核对不过，禁止上传/发布（防"构建漏带晚改文件"）。

---

## 二、批次生命周期（6 步，每步落盘）

| 步骤 | 操作者 | 动作 | 落盘 |
|---|---|---|---|
| 1 登记 | Dev | 构建成功 → 写交接单 + 更新批次清单为「待核对」 | `docs/发布协作/交接单/REL-YYYYMMDD-NNN-<任务编号>.md` |
| 2 核对 | Release | `bash scripts/release_check.sh <交接单>`，exit 0 才继续 | 交接单追加「核对结果」段 |
| 3 测试 | QA + PM | Gate D 过门 → 本地测试（回归/冒烟/联调）→ Gate T 过门 | 状态改「待测试」→「待发布」 |
| 4 发布 | Release | 窗口确认 → 建回滚点 → 预检 → 同步 → 构建 → 迁移 → 验证（见 §四） | 状态改「已发布」+ 台账 |
| 5 留观 | Monitor | 30 分钟观察日志/任务/对账；异常按 `生产发布清单.md` 处置 | 交接单追加「留观结论」 |
| 6 归档 | Release | 已发布批次移入 `发布归档-历史批次.md`，主清单保留索引 | 归档文件 |

## 三、门禁对接（Gate D/T/P）

| 门 | 判定人 | 本机制提供的机器证据 | 其余人工核对项（见 M07-4 §四~六） |
|---|---|---|---|
| Gate D 开发门 | PM | 交接单 + `release_check.sh` exit 0（构建完整性） | 查重 / 规范 0 违规 / 单测全绿 / 自测文档 |
| Gate T 测试门 | QA + PM | 测试报告落盘 | healthz / 回归全绿 / P0-P1 清零 |
| Gate P 生产门 | Release + PM | 预检 0 失败 / 健康 3/3 / 生产验证 39 项 | 窗口 / 回滚点 / 资金附加检查（对账 0 差异） |

**资金相关变更（结算/提现/对账/会员权益）**：额外执行 `生产发布清单.md` §三 三项，缺一即终止发布。

**测试环境判定规则（2026-09-06 补充，PM 确认）**：
- 测试环境 = 本地 Mac（`.env.test` + 独立库 `gaking_test` + 端口 3001），非独立测试服务器。
- **部署/迁移/配置/依赖类改动**（Dockerfile、alembic 迁移、环境变量、依赖增减）→ **必检项**：执行 `deploy_backend.sh test` 干净部署 + 回归，验证部署链路与全新库升级。
- **纯逻辑改动**（接口逻辑、bug 修复，不触部署链路）→ 可在开发环境直接回归，测试结论标注「逻辑改动，开发环境回归」，免测试部署。
- 测试结论统一落盘交接单「测试结论」段，作为 Gate T 证据。

## 四、发布标准命令（Release 执行，按序）

```bash
# 0) 发布前探测未登记改动（硬约束②）
cd /Users/alexzhang/Documents/Work/Projects/Products/金角大王/GAKing-Coding
git status --short                     # 有改动但批次清单未登记 → 先补占位批次
find . -newer <最近交接单> -name "*.py" -o -name "*.js" 2>/dev/null | head   # 检查晚改文件

# 1) 硬闸门
bash scripts/release_check.sh "docs/发布协作/交接单/REL-XXXXXXXX-NNN-<任务编号>.md"   # exit 0 才继续

# 2) 测试环境（本地 Mac，端口 3001）
bash scripts/deploy_backend.sh test        # .env.test + 测试库
bash scripts/pre_deploy_check.sh           # 非生产，DB 项可跳过
bash scripts/s05_regression_admin.sh && python3 scripts/s04_smoke_test.py
python3 scripts/s07_admin_retest.py && python3 scripts/s07_miniapp_retest.py
python3 scripts/s06_full_chain_test.py

# 3) 生产（服务器 124.70.196.241，窗口 周三/四 22:00-24:00）
ssh -i <密钥> root@124.70.196.241 'cd /opt/gaking/deploy && docker tag gaking-backend:prod gaking-backend:prev && docker tag gaking-admin:prod gaking-admin:prev'   # 建回滚点
ssh ... 'cd /opt/gaking/backend && bash ../scripts/pre_deploy_check.sh --remote --with-db'   # 预检 0 失败
rsync -av --exclude '.env.production' --exclude 'deploy/.env' --exclude '.env*' --exclude '*.pem' --exclude 'node_modules/' --exclude 'venv/' --exclude '.venv/' --exclude '__pycache__/' --exclude '*.pyc' --exclude 'dist/' --exclude 'build/' --exclude 'dump.rdb' --exclude 'start-dev.md' --exclude '本地启动指令.md' --exclude 'gak-logo*' --exclude 'logs/' --exclude 'inspect/' --exclude '.DS_Store'   # 同步（排除敏感文件；⚠️ 禁止 --delete，会误删服务器独有文件如 dump.rdb/docs/sql）
ssh ... 'cd /opt/gaking/deploy && docker compose up -d --build && docker compose exec backend alembic upgrade head'
# ⚠️ 顺序铁律：rsync 只同步宿主机 → 必须 compose up -d --build（重建镜像 COPY 新代码）→ 容器内才有新迁移文件 → 才能 alembic upgrade head（S17-1 实战教训）
# ⚠️ 手动跑 alembic 必须显式带环境：ENVIRONMENT=test .venv/bin/alembic upgrade head（否则默认 development 连错库；deploy_backend.sh 已自动 export）
ssh ... 'bash /opt/gaking/scripts/health_check.sh http://localhost:3003'       # 3/3 healthy
python3 scripts/s04_prod_verification.py     # 39 项全过
# 4) 留观 30 分钟（Monitor）
```

> 完整命令与回滚见 `部署与发布手册.md` §六 / `生产发布清单.md` §四。

## 六、双硬约束（血泪教训固化）

1. **构建即登记**：任何代码改动本地构建成功，**必须当场登记批次+交接单**（哪怕小改、哪怕不马上发布）。禁止"构建了但不说"，让运维去猜。
2. **发布前先探测未登记改动**：每次发布不能只读清单，必须先 `git status --short` + 检查构建产物新时间戳；发现有改动但清单没登记 → 先补占位批次等交接单，**不得逆向比对产物猜开发意图**。
